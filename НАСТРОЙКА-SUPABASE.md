# Supabase: восемь шагов

**Для проекта wallet-byn всё это уже сделано.** Таблица создана, права выданы,
подтверждение почты выключено, оба значения вписаны в `config.js`. Инструкция
остаётся на случай, если понадобится поднять базу заново или с нуля.

Нужны только два публичных значения: адрес проекта и публикуемый ключ. Пароль
базы, секретный ключ и JWT secret нигде в приложении не используются и никуда
передавать их не надо.

**1. Регистрация.** Открой `supabase.com`, нажми **Start your project**, войди
через GitHub или почту. План Free, карта не нужна.

**2. Проект.** Кнопка **New project**.
- Organization — та, что создастся сама
- Name — например `wallet`
- Database Password — придумай и сохрани у себя. Приложению он не нужен, но
  Supabase его больше не покажет
- Region — **Frankfurt (eu-central-1)**, ближе всех к Беларуси
- Нажми **Create new project** и подожди две-три минуты

**3. Таблица.** Слева **SQL Editor**, кнопка **New query**. Вставь целиком
содержимое файла `supabase.sql` из этой папки, нажми **Run** (или Ctrl+Enter).
Внизу должно появиться **Success. No rows returned**. Один раз, больше не надо.

**4. Проверка, что таблица встала.** Слева **Table Editor**, в списке должна
появиться таблица `wallet_docs` со столбцами `user_id`, `path`, `data`,
`version`, `updated_at`. Рядом с именем таблицы должна стоять пометка про
включённый **RLS**. Если пометки нет — значит шаг 3 выполнился не полностью,
повтори его.

**5. Project URL.** Слева внизу **Project Settings**, раздел **Data API**,
поле **API URL**, вида `https://abcdefgh.supabase.co`. Он же виден в адресе
панели: `dashboard/project/<вот это и есть имя проекта>`.

**6. Ключ.** **Project Settings**, раздел **API Keys**. Нужна строка
**Publishable key**, она начинается на `sb_publishable_`. В проектах постарше
на её месте ключ **`anon` `public`** в виде длинной строки на `eyJ`, годится
любой из двух. Строку **Secret key** (в старых проектах **`service_role`**) не
трогай вообще: она даёт полный доступ в обход защиты и в приложении не нужна.

**7. Вход по почте.** Слева **Authentication**, дальше **Providers**, пункт
**Email**. Он включён по умолчанию, ничего менять не обязательно.
- Хочешь, чтобы аккаунт работал сразу, без письма на почту — выключи
  **Confirm email** и нажми Save. Так проще, и для личного кошелька этого
  достаточно
- Оставишь включённым — после создания аккаунта придёт письмо со ссылкой, по
  ней надо перейти один раз
- Ничего другого в Authentication включать не надо: ни сторонних провайдеров,
  ни анонимный вход

**8. Два значения в файл.** Открой `config.js` из этой папки и вставь их в
кавычки:

```js
window.WALLET_SUPABASE = {
  url: "https://abcdefgh.supabase.co",
  anonKey: "sb_publishable_..."
};
```

Оба значения публичные по замыслу Supabase: сам по себе ключ ничего не
открывает, доступ к строкам закрывает политика RLS из шага 3 — она пускает
каждого только к его собственным записям. Поэтому `config.js` спокойно лежит
в открытом репозитории.

## Про права на таблицу

В `supabase.sql` есть строка `grant select, insert, update, delete ... to
authenticated`. Она обязательна: в новых проектах Supabase роль вошедшего
пользователя по умолчанию не получает прав на таблицу, и приложение падает с
`permission denied for table wallet_docs` ещё до проверки политики. Роли `anon`
права намеренно не выдаются, без входа приложение в базу не ходит.

## Когда заведёшь себе аккаунт в приложении

Стоит закрыть вход чужим: **Authentication**, **Sign In / Providers**, тумблер
**Allow new users to sign up** выключить. Твой собственный вход продолжит
работать, а посторонние зарегистрироваться в проекте уже не смогут. Чужие
данные они и так бы не увидели, это закрывает RLS, но лишние аккаунты в твоём
проекте ни к чему.
